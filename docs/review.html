What Works — Don't Touch These

VERIFIED ✓
  • Explicit state machine with a transition table. legalTransitions in job.go is the correct pattern. No scattered if status == anywhere. The illegal-transition tests cover every meaningful edge case and all pass.
  • Transactional Outbox + reconciliation loop (ADR 007/008). The only safe way to bridge a DB write and a broker publish. The FOR UPDATE SKIP LOCKED on the outbox is exactly right for concurrent dispatcher replicas.
  • Fencing token on every write (ADR 002/009). Protects against the GC-pause zombie-write scenario. The WHERE fencing_token = :held_token condition on state updates is essential and present in the repository interface contract.
  • BackoffStrategy interface with Full Jitter. Properly decoupled behind an interface, deterministically testable with ConstantBackoff, and references the AWS canonical jitter paper. The bounds tests pass correctly.
  • Repository + Transactor interfaces. All four repositories plus the Transactor are pure interfaces. Every service method is testable without a live Postgres, Redis, or RabbitMQ instance.
  • Cascading abort on parent failure (ADR 010). Dependent jobs are automatically cancelled when a parent reaches a terminal failure. Prevents zombie jobs that block the scheduler queue indefinitely.
  • api_key_hash is excluded from JSON serialization. json:"-" on Tenant.APIKeyHash ensures the hash is never accidentally leaked in API responses.

Proto priority ordinals ≠ domain priority weights — silent scheduling corruption
proto/v1/job.proto vs internal/domain/job.go
CRITICAL

Verified by reading both files. The domain uses numeric weights as actual ORDER BY priority DESC values stored in Postgres: 

PriorityLow      = 0    // domain weight → stored in DB
PriorityDefault  = 2
PriorityHigh     = 5
PriorityCritical = 10

The proto enum uses sequential ordinals 1–4: 

JOB_PRIORITY_LOW      = 1    // proto ordinal → NOT the DB weight
JOB_PRIORITY_DEFAULT  = 2
JOB_PRIORITY_HIGH     = 3
JOB_PRIORITY_CRITICAL = 4

If the gRPC handler naively casts int32(req.Priority) to domain.JobPriority without an explicit mapping, a CRITICAL job is stored with weight 4 instead of 10, and a HIGH job with 3 instead of 5. Both will sort below a default-priority job (weight 2 → stored as 2, which happens to match). The bug is silent because default jobs have the same ordinal as their domain weight.

Required explicit mapper in the gRPC handler layer 
func protoToDomainPriority(p v1.JobPriority) domain.JobPriority {
    switch p {
    case v1.JobPriority_JOB_PRIORITY_LOW:      return domain.PriorityLow      // 0
    case v1.JobPriority_JOB_PRIORITY_HIGH:     return domain.PriorityHigh     // 5
    case v1.JobPriority_JOB_PRIORITY_CRITICAL: return domain.PriorityCritical // 10
    default:                                   return domain.PriorityDefault  // 2
    }
}

Warnings

DESIGN GAPS
TransitionTo() does not update UpdatedAt — stale timestamps in responses
internal/domain/job.go · line 99
WARNING

The Postgres trigger trigger_jobs_updated_at updates the column on disk, but the in-memory Job object returned from a service method still carries the timestamp from when it was last read. Any gRPC response that returns the domain object directly will surface a stale updated_at to the client without a round-trip re-read from the database.

One-line fix in TransitionTo() 
 func (j *Job) TransitionTo(next JobStatus) error {
     if err := ValidateTransition(j.Status, next); err != nil {
         return err
     }
     j.Status = next
+    j.UpdatedAt = time.Now().UTC()
     return nil
 }
Outbox RetryCount has no ceiling — reconciler loops forever on a dead message
internal/domain/outbox.go · OutboxEvent
WARNING

MarkFailed increments retry_count, but there is no MaxOutboxRetries constant and no dead-letter path for an outbox event that has failed more than N times. If RabbitMQ is persistently unavailable or a message is permanently malformed, FetchUnpublished will keep picking up the same row on every reconciliation tick, burning query budget and polluting logs without any circuit breaking.

Add a MaxOutboxRetries = 10 constant in the domain, and in the reconciler: skip (or transition to an abandoned status) any outbox row where retry_count >= MaxOutboxRetries.

No domain constructor for Tenant — plaintext API key can be stored silently
internal/domain/tenant.go
WARNING

api_key_hash VARCHAR(64) implies SHA-256. The comment in TenantRepository.GetByAPIKeyHash says "SHA-256 API key hash". But nothing in the domain enforces that only a hash reaches the database. A caller can construct a domain.Tenant struct literal with a raw plaintext key and pass it to TenantRepository.Create() — the type system will not stop them.

Add a constructor that enforces the invariant 
func NewTenant(name, rawAPIKey string) (*Tenant, error) {
    if rawAPIKey == "" {
        return nil, errors.New("api key must not be empty")
    }
    h := sha256.Sum256([]byte(rawAPIKey))
    return &Tenant{
        ID:         uuid.New(),
        Name:       name,
        APIKeyHash: hex.EncodeToString(h[:]),
        CreatedAt:  time.Now().UTC(),
    }, nil
}
DependsOn is a single UUID — no cycle detection, no fan-in
internal/domain/job.go · Job.DependsOn
WARNING

The current schema supports exactly one parent per job. If a client submits Job A depending on Job B, and Job B depending on Job A, the cascade abort (ADR 010) never fires because neither job reaches a terminal state on its own. This is a distributed deadlock with no self-healing path. There is no cycle-detection anywhere in the domain or repository layer.

At minimum, on job submission the scheduler must walk the dependency chain upward and reject any submission that would form a cycle. A simple ancestor-set check at submit time is sufficient given the single-parent model.

These need integration tests against a real Postgres in Docker, using testcontainers-go or a local compose service in CI.
